## Executive Summary & Non-Simulation Mandate

> [!CAUTION]
> **Strict Architectural Mandate**: Do **NOT** invent, reverse-engineer, or fake a proprietary Hikvision P2P protocol.
> Hikvision devices registered under consumer EZVIZ or Hik-Connect utilize closed, undocumented UDP hole-punching and cloud relay protocols that frequently change with firmware updates. Any homebrew P2P simulation is brittle, insecure, violates vendor terms, and causes catastrophic connection drops in enterprise multi-branch environments.

LensIQ enforces that:
1. All physical Hikvision integrations **MUST** use officially supported vendor mechanisms.
2. The platform isolates all Hikvision-specific logic strictly behind the [`IVideoSourceAdapter`](file:///Users/POM/Developer/personel/lensIQ/src/backend/streaming/adapters/video-source.adapter.ts) interface via [`HikvisionP2PSourceAdapter`](file:///Users/POM/Developer/personel/lensIQ/src/backend/streaming/adapters/hikvision-p2p-source.adapter.ts).
3. If official SDK/Cloud credentials are not yet present in the deployment environment, the system strictly operates in **Demo Mode** or reports an explicit `unsupported` status without claiming a fake live hardware connection.
4. Mobile (Flutter) and Web clients **never** interface with Hikvision protocols or credentials directly; they interact exclusively with the Streaming Gateway's WebRTC and HLS endpoints.

## 6-Point Technical Evaluation

### 1. Officially Supported Hikvision Integration Methods

Hikvision officially provides three enterprise integration pathways:

| Method | Description | Network Model | Video Transport | Suitability for LensIQ |
| :--- | :--- | :--- | :--- | :--- |
| **A. Hik-Connect Open Platform / Hik-Partner Pro OpenAPI** | Cloud REST APIs provided by Hikvision for devices bound to Hik-Connect cloud accounts. | Outbound HTTPS from Gateway to Hikvision Cloud API. Devices connect outbound to Hik-Connect. | Cloud-relayed HLS (`.m3u8`), RTMP, or WebRTC (`webrtc://`) streams generated by Hikvision media clusters. | **Primary Recommended Integration** for remote cameras behind NAT without port forwarding or static IPs. |
| **B. ISUP 5.0 (formerly Ehome protocol)** | Direct device-to-server push protocol over WAN. The camera/NVR is configured with the Gateway's public IP/domain. | Camera pushes inbound connection to Gateway server over TCP/UDP. | RTP/RTCP or MPEG-PS video stream over TCP. | **Optimal for High-Density Enterprise**: Eliminates per-camera cloud subscription costs while traversing WAN/firewalls without inbound port forwarding. |
| **C. HCNetSDK (Device Network C/C++ SDK)** | Native C/C++ library (`libhcnetsdk.so` / `HCNetSDK.dll`) connecting directly to camera/NVR IP and port 8000. | Inbound connection from Gateway to Camera IP/Port. | Raw packet callback (`fRealDataCallBack_V30`) yielding PS/H.264/H.265 frames. | Best for local edge appliances or VPN-linked branches; requires native binary runtime. |

### 2. Server Operating System Availability

| Target OS | Cloud OpenAPI | ISUP 5.0 Gateway | HCNetSDK (Native C++) |
| :--- | :--- | :--- | :--- |
| **Linux x86_64** (Ubuntu 22.04 LTS / Debian 12 / Alpine) | Full Support (100% Node.js / Python compatible) | Full Support (Standard Linux TCP sockets) | Full Support (`libhcnetsdk.so` compiled for glibc x86_64; musl/Alpine requires glibc compatibility layer). |
| **Linux ARM64 / aarch64** (AWS Graviton, Apple Silicon Docker) | Full Support | Full Support | **Severely Limited**: Hikvision only provides ARM binaries for specific embedded HiSilicon toolchains, not standard `aarch64` Linux distributions. |
| **Windows Server** (2019/2022) | Full Support | Full Support | Full Support (`HCNetSDK.dll`). |

**Conclusion:** Utilizing the **Hik-Connect Cloud OpenAPI** or an **ISUP 5.0 media termination layer** provides cross-architecture portability (x86_64 and ARM64), whereas HCNetSDK locks deployment to Linux x86_64 glibc containers.

---

### 3. Licensing Requirements

1. **Hik-Connect Open Platform / Hik-Partner Pro:**
   * Requires an enterprise developer account at the [Hikvision Open Platform Portal](https://open.hikvision.com).
   * Developer Agreement approval and issuance of `AppKey` and `AppSecret`.
   * Concurrent live streaming may incur cloud relay bandwidth quotas or tier fees depending on the target region (EU, NA, MEA).
2. **ISUP 5.0 Protocol:**
   * **Royalty-Free**: Built into the firmware of all contemporary Hikvision IPCs, DVRs, and NVRs (firmware 4.x+).
   * No recurring licensing fees to Hikvision.
3. **HCNetSDK:**
   * Free to download under Hikvision SDK agreement; redistribution in commercial appliances is permitted subject to standard vendor licensing terms.

---

### 4. Authentication Requirements

1. **Cloud OpenAPI:**
   * HMAC-SHA256 request signature incorporating `AppKey`, `AppSecret`, timestamp, and nonce.
   * Short-lived Bearer tokens (`accessToken`) refreshed every 7 days.
   * Device Verification Code (6-character sticker code on camera) required to decrypt the video stream if Hik-Connect stream encryption is enabled.
2. **ISUP 5.0:**
   * Device ID (assigned in camera settings).
   * ISUP Registration Password / Key (mutual pre-shared secret between device and gateway).
3. **HCNetSDK:**
   * Device IP, Port (`8000`), Username (`admin`), and Device Password.
   * Or Hik-Connect verification code for cloud-linked devices.

---

### 5. Live Video Frames & Stream Delivery

* **Can it provide live frames?**
  * **Yes**. Cloud OpenAPI generates temporary HLS or WebRTC URLs routed via Hikvision Cloud edge servers.
  * ISUP 5.0 pushes raw H.264/H.265 bitstreams directly to the Gateway server.
  * HCNetSDK invokes a C callback with each video frame chunk, which can be piped to FFmpeg or MediaMTX for transcoding into HLS and WebRTC.

---

### 6. Production Server Reliability

* **Node.js Thread Safety & Memory Leaks:**
  * Direct invocation of C/C++ `HCNetSDK` from Node.js via FFI (`ffi-napi`) introduces risks: unhandled C++ exceptions or memory corruptions terminate the entire Node.js event loop.
  * **Architectural Decision**: If native HCNetSDK is utilized, it **MUST** be deployed inside a dedicated, isolated Sidecar container (written in Go or C++) communicating with the Node.js Streaming Gateway via gRPC or internal Unix domain sockets.
  * Cloud OpenAPI and ISUP avoid native C runtime dependencies, offering 99.99% Node.js process stability.

## Missing Dependencies Checklist for Physical Hardware

When connecting physical Hikvision hardware in subsequent deployment phases:

1. [ ] **Hikvision Developer Credentials**: `HIKVISION_APP_KEY` and `HIKVISION_APP_SECRET` populated in the environment or Vault.
2. [ ] **Device Registration**: Camera/NVR enrolled in Hik-Connect Cloud, with verification code recorded in `credentials_reference`.
3. [ ] **Or ISUP 5.0 Listener**: Port `7660` (default ISUP registration port) opened on Gateway firewall and camera configured with Gateway WAN IP.
4. [ ] **MediaMTX / FFmpeg Transcoder**: Ingest worker container configured to package raw camera feeds into WebRTC tracks and HLS segments.
